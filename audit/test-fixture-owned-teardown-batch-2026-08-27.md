# KINGA Test Fixture Lifecycle Batch 1 — Exact Ownership Evidence

**Scope.** This review-only batch hardens the eight approved database-mutating test suites. Every teardown is registered at suite definition time, guards partial setup, removes child records before parents, and performs a post-delete no-leak assertion. No migration, DDL, production code path, payment, policy, settlement, authentication, or provider integration changed.

The cleanup rule is deliberately narrow: a deletion may use only a primary key returned by that suite’s own insert or router mutation, or a complete immutable sentinel generated by that suite. Child rows discovered immediately before cleanup are first reduced to an exact parent primary key that is already known to be test-owned; their captured child primary keys, rather than a tenant-wide or pattern predicate, are then deleted.

## Owned lifecycle claim substitute

The former lifecycle test required an existing claim only incidentally. Its actual workflow calls require a tenant, numeric actor ID, a claim beginning in `workflowState: "created"`, valid basic vehicle/incident data, a tenant-scoped active automation policy, and an assessment record before later workflow stages. The new fixture supplies precisely those conditions. Its assessment and routing assertions remain conditional where the original tests were conditional; no historical claim characteristics are assumed.

## Borrowed-record audit

The static scan covered all test/spec source files and found four unfiltered single-row query candidates. Only `test-claim-lifecycle.test.ts` subsequently mutated the selected entity. `audit-01.test.ts` read an audit row, `e2e-real-claim.test.ts` read a physics row, and `test-analytics-validation.test.ts` read an automation policy; none mutates its selected row. The lifecycle suite’s arbitrary claim selection was removed in this batch. The machine-readable scan evidence is retained in `borrowed-row-mutation-ast-findings.json` outside this repository’s source tree.
